# AGENTS.md

Инструкции для AI-ассистентов, работающих в этом репозитории.

## О проекте

**«Тренажёр английского»** — статическое PWA-приложение (vanilla JavaScript, без сборки и
зависимостей): показывает русское предложение из базы Tatoeba, пользователь пишет английский
перевод, приложение сверяет с оригиналом и проверяет грамматику локально (harper.js).

- Публикуется на GitHub Pages: репозиторий `ru2eng/ru2eng.github.io`, push в `main` = публикация.
- Клиент работает офлайн (Service Worker + Cache API); все данные и настройки хранятся локально.
- Язык интерфейса, комментариев, commit-сообщений и документации — **русский**.

## Стек и окружение

- Фронтенд: ES6+ (`const`/`let`, стрелочные функции, `async/await`), DOM без фреймворков.
- **Сборки и npm нет**. Локальный запуск: `start.bat` (Python `http.server`, порт 8000)
  или `python -m http.server 8000` / `npx serve`. Требуется HTTP/HTTPS (не `file://`).
- Данные собирает Python-скрипт `tools/build_index.py` (см. `python tools/build_index.py --help`).
- Node в системе может отсутствовать — не полагайтесь на `node --check` для проверки JS
  (проверяйте глазами и в браузере через `start.bat`).
- ОС: Windows/PowerShell. Git предупреждает про LF→CRLF — это норма, не исправлять.

## Структура

```
index.html            # основной тренажёр (SPA-каркас)
settings.html         # настройки: тема, «Скачать все данные» (офлайн-предзагрузка)
guide.html            # руководство пользователя
app.js                # логика тренажёра (IIFE-модуль)
dl.js                 # офлайн-предзагрузка данных (самодостаточный модуль)
theme.js              # переключение темы (подключён на всех страницах)
sw.js                 # Service Worker: shell (stale-while-revalidate) + данные (cache-first)
styles.css            # стили; тёмная/светлая темы через [data-theme]
data/                 # сгенерированные данные, коммитятся (~140 МБ), один файл = одна строка JSON
tools/build_index.py  # сборщик data/ из дампов Tatoeba
vendor/harper/        # локальный проверщик грамматики (WASM)
manifest.webmanifest  # PWA-манифест
icons/                # иконки PWA
```

## Команды

- Запуск локально: `start.bat` → http://localhost:8000
- Пересборка данных: `python tools/build_index.py` (опции `--out`, `--skip-download`, `--chunk-size`, `--limit`)
- Публикация: `git add -A && git commit -m "..." && git push origin main`

## Конвенции и правила правок

**Архитектура**
- `app.js` — одно IIFE-замыкание. Всё, что не про тренажёр, выносится в отдельный модуль
  (как сделано с `dl.js`, `theme.js`); модуль самодостаточен и устойчив к `document.getElementById(...)` = null
  (проверки `hasUi`/`if (el.x)`).
- Страницы могут жить без `app.js` (`settings.html`, `guide.html`) — общий код только в `dl.js`/`theme.js`.
- Данные — чанкованные: манифест (`data/manifest.json`, поля `widx`/`packs`/`ru`, версия `build_date`)
  + чанки `widx/widx_<c>.json`, `packs/pack_<b>.json`, `ru/ru_<b>.jsonl`. Клиент качает только нужное.
- Аудио: `https://api.tatoeba.org/v1/audios/{id}/file` (`a` в паке — id аудиозаписи из
  `eng_sentences_with_audio.tsv`). Внимание: API периодически недоступен (503) — при изменениях
  аудио-логики помните о возможном фолбэке на `https://audio.tatoeba.org/sentences/eng/{id}.mp3`.
- Тема: `theme.js` на всех страницах; выбор в `localStorage['tatoeba-theme']`.

**Service Worker (`sw.js`)**
- Кеши: shell `tatoeba-shell-vN`, данные `tatoeba-data-v1`.
- При добавлении/переименовании статического файла: добавить его в `SHELL` **и поднять версию**
  shell-кеша, иначе установленные клиенты получат старый остов (stale-while-revalidate подтянет
  только при следующем открытии).
- Новые страницы обязаны быть в `SHELL` и регистрировать SW (скрипт-болванка в конце HTML).
- Данные в `data/` нельзя пушить в `DATA_CACHE` при install — только по мере использования
  (cache-first) или через предзагрузку `dl.js`.

**Данные и лимиты**
- Каталог `data/` коммитится намеренно; лимит GitHub Pages — 100 МБ **на файл**, большие чанки ~9 МБ — ок.
- Файлы чанков — минифицированный JSON в одну строку: универсальный grep/чтение может не работать
  (длинные строки) — используйте точечные инструменты или скрипты.
- Механика инвалидации данных: SW при `manifest.json?check=` сравнивает `build_date` и при изменении
  чистит `DATA_CACHE` (кроме случая, когда манифеста в кеше ещё не было).

**Тесты и проверка**
- Отдельного тестового раннера нет. Проверка выполняется вручную в браузере через `start.bat`:
  поиск слова → ответ → аудио → тема → предзагрузка данных на `settings.html` → офлайн после установки PWA.

## Чего не делать

- Не раздувать зависимости (проект без npm/билда).
- Не отправлять данные пользователя на сервер; машинный перевод и аудио — исключения (внешние сервисы).
- Не менять формат чанков (widx/packs/ru) без синхронной правки `app.js` и `tools/build_index.py`.
- Не оставлять незакоммиченных данных после пересборки без проверки `data/manifest.json` (build_date).
